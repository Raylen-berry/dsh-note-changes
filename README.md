# DSH 笔记库 · v1.11.0

在 DSH Desktop 的已有会话中打开 **笔记** 插页，与费用、Q、小游戏并列，进入 Obsidian 风格的完整笔记工作区：左侧文件树、中间正文与编辑器、右侧大纲和双链。切回对话后再返回，未保存草稿会恢复。

左右栏固定在工作区内：搜索、新建和栏目标题保持可见，长目录、大纲与链接各自在列表内部滚动。正文独立滚动；切回对话后恢复 Desktop 原有滚动行为。

## 可以做什么

- 浏览本地 Markdown 目录，包括尚未提交的草稿；按标题与正文搜索。
- 阅读常用 Markdown，沿 `[[双链|别名]]` 跳转，查看大纲、出链与反向链接。同名笔记提供候选，不自动猜。
- 切换到 Markdown 编辑器，保留原始 frontmatter 和双链；按保存或 Ctrl/Cmd+S 写回当前文件。
- 切换笔记会在当前浏览器会话暂存草稿；刷新后重新打开可恢复。草稿仍需手动保存，关闭浏览器会话后不保证保留。
- 查看 Git 改动历史；在设置页管理本机路径、AI 记录与同步。
- 新建笔记与多级目录，选择空白、每日或会议模板；“今日笔记”遇到已有文件直接打开。收藏与最近打开按笔记库保存在本机浏览器。
- 用标签、常用 frontmatter 属性和值组合筛选；查看局部关系图与孤立笔记。图中仅连明确解析的双链，同名歧义不会猜测。
- 用 `40-提示词/` 存提示词资产（模板 / 工作流 / 案例 / 经验）；字段口径见该目录的说明笔记，agent 侧由 `prompt_asset_save` 收录。
- 预览库内图片、音频、视频，打开 PDF 附件；支持 `![[附件]]` 和 Markdown 相对附件路径。行内 `$...$` 与独立 `$$` 块用本地 KaTeX 排版。

工作区使用普通 Markdown 文件，没有加载 Obsidian 的第三方插件、Canvas 或 Dataview。属性筛选支持顶层单值、内联列表与缩进列表；复杂 YAML 不参与筛选，编辑时仍保留原文。图片限 PNG/JPEG/GIF/WebP/AVIF，媒体限 MP3/WAV/OGG/M4A/MP4/WebM（播放能力依浏览器），单附件上限 20 MB；PDF 使用本地新页入口。远程图片显示可点击链接，不自动加载；SVG 与其他主动内容不提供嵌入预览。

提示词资产由 `prompt_asset_save` 收录：字段收敛成参数、由代码拼 frontmatter（漏一个字段就少一条筛选路，且不会报错），落盘走原子的 create-if-absent，写完沿用同一套单文件提交推送。它是给**已经写完**的提示词用的——批次里还是「（待填…」的占位条目会被拒绝，否则建出来的是一排空壳资产。同名已存在同样拒绝：资产优先新建，要改就在笔记页打开它。

## 保存与冲突

读取时记下正文版本；保存时再次核对版本，并交给宿主文件服务做原子替换。如果 Obsidian、另一窗口或自动日记已改过文件，返回冲突并保留草稿。“对照合并”将磁盘新版与草稿并排展示，相同内容自动保留，每处差异可选磁盘、草稿或两段都保留；全部选完后应用到草稿，再手动保存。长文超过差异计算预算时按整篇对照。再次发生外部修改时，保存仍会拦截；新建使用原子 create-if-absent，不覆盖同名笔记。

保存后沿用原有同步：只暂存 **并只提交** 当前文件，推送失败显示回执，本地修改仍保留。Git 操作按笔记库排队。自动日记仍受原有开关控制；用户主动点击保存独立于该开关。

超过 60,000 字符只预览，不允许把截断内容写回；超过 1 MB 的单篇请用 Obsidian。检索最多收集 2,000 篇笔记及 2,000 个附件、500 个目录、16 层深度，正文预算 8 MB；超过范围明确显示部分索引。目录、正文和附件都校验实际目标在库内，跳过隐藏目录与 node_modules。刷新时根据宿主文件版本复用未改正文，只重读新增与修改项并移除删除项；底栏展示本次读取与复用数。索引缓存在内存中，不写入或上传笔记原文。

## 安装与本机路径

安装 `github:Raylen-berry/dsh-note-changes#main` 后重启 DSH Desktop，使宿主和客户端一起更新。需要带 `conversation.view` 扩展接口的 Desktop（已按当前本机组件核对）。入口在会话页顶部“笔记”，旧侧栏入口已移除；全局设置中的笔记设置仍可用。尚未开始的新会话是否显示插页由 Desktop 控制。

路径优先级保持不变：显式参数 / 设置页覆盖 → `DNC_VAULT` → `$DSH_HOME/dsh-note-changes/vault.txt` → 笔记库设置 → 默认值。换机器可在指针文件写一行本地绝对路径。插件不修改 `.obsidian/`。

设置页只有两个互斥的连接方式：**跟随本机配置** 或 **指定笔记库文件夹**。选择后点击一次“应用连接”才生效；指定文件夹不允许留空，不再偷偷回退为跟随模式。先检查目录可读，再保存路径并刷新工作区。当前生效的模式和路径始终可见，无效路径保留原连接。

兼容新版 Desktop 的 `shell.execute(...).result()` 与旧版 `shell.run(...)`。推送失败保留具体原因，回执按笔记库区分。

## GitHub 作为两台电脑的中转站

两台电脑各自克隆同一个 GitHub 笔记仓库，关联相同远端分支，并在本机设置里连接对应文件夹。路径可以不同；Git 需要已登录 GitHub、具备仓库权限，并配置提交作者。首次克隆仍通过 Git 完成，插件不会创建远端仓库或自动公开任何库。

1. 在当前电脑开始写之前，点击 **下载更新**。
2. 在 Obsidian 或本插页编辑笔记。写完后点击 **上传笔记**。
3. 到另一台电脑先点击 **下载更新**，继续写，再上传。

上传会提交本机新增、修改及删除的 Markdown 与常见附件（PNG/JPEG/GIF/WebP/AVIF/SVG、MP3/M4A/WAV/OGG、MP4/WebM、PDF，单文件不超过 20 MB）。遵守 `.gitignore`，排除隐藏目录、node_modules、根目录 AGENTS.md/SKILL.md 和其他类型。同步范围可展开检查；已有 Git 提交整体随分支上传。编辑器的保存按钮仍只提交当前文件并尝试自动推送。

下载不会替你提交、丢弃或临时藏起改动；有未提交笔记时提示先上传。未追踪的本机配置无需上传，也不会被清除；若与远端文件重名，Git 会阻止覆盖。上传遇到远端的新提交会先合并：无冲突继续；内容冲突会中止变基、恢复本机提交并列出冲突文件，需在 Git/Obsidian 工作流中处理后重试，不强推远端。编辑器草稿需先保存，跨插页和跨库草稿仍保留。

同步只接受仓库根目录，使用当前分支的跟踪远端；本机写入、自动日记和 Git 同步按库排队。不会自动提交范围外的已跟踪改动；有这些改动或未结束的合并时提示先处理。每次最多自动提交 500 个文件，并限制命令长度；更多改动请先用 Git 分批提交。页面计数来自最近获取的远端状态，每次上传/下载都会重新获取。

## 开发与检查

```sh
npm run build
npm run check
npm test
node tools/browser-check.mjs
node tools/browser-plus-check.mjs
node tools/browser-settings-check.mjs
```

- `client/workspace.part.js`：页面与状态；`client/markdown.part.js`：Markdown 阅读与链接解析；`client/plus.part.js`：创建、合并、关系图与附件组件；`client/styles.css`：主题和窄屏样式。
- `client.js` 自动生成，不直接修改。
- `lib/vault-browser.mjs`：有界扫描、检索缓存、路径和版本保护。
- `lib/vault-sync.mjs`：双向同步、范围检查与冲突恢复；离线检查使用真实 Git 裸仓库和两个临时克隆模拟两台电脑。
- 浏览器检查使用临时笔记库和模拟 Git 同步，不读写真实笔记、不调用模型。可配置 `DNC_PLAYWRIGHT_MODULE`、`DNC_REACT_ROOT`、`DNC_BROWSER`、`DNC_SCREENSHOTS`；Windows 默认使用现有 Edge。
- 原有追加、同步、路由回归继续执行。早期实现记录见 [历史文档](docs/v1.7-history.md)。
- 公式资源固定为 [KaTeX 0.18.9](https://katex.org/docs/api.html)，随插件发布，见 [第三方资源说明](vendor/README.md)。

## 回退

回退本次提交并重新安装 / 重启即可。笔记仍是普通本地 Markdown 文件，UI 回退不会删除它们；本版没有修改笔记库内容或 `.obsidian` 配置。
