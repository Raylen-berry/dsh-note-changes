# GitHub 与两台电脑同步

[返回首页](../README.md) · [文档导航](README.md)

两台电脑分别保留一份本地笔记，GitHub 笔记仓库作为中转站。本插件的代码仓库与存放自己笔记的仓库是两回事。

## 一次性准备

1. 准备自己的 GitHub 笔记仓库，并在两台电脑分别克隆。
2. 两边关联同一个远端分支；本机文件夹路径可以不同。
3. 在各自插件设置里连接该仓库的根目录。
4. 确认本机 Git 已配置提交作者，能访问并推送这个远端。

首次克隆由 Git 完成。插件不会创建远端仓库，也不会替你改变仓库的公开或私有状态。

## 每次怎么用

1. 开始写之前点 **↓ 下载更新**。
2. 在 Obsidian 或笔记插页中编辑，先保存编辑器草稿。
3. 写完点 **↑ 上传笔记**，查看成功或错误回执。
4. 到另一台电脑，先下载更新，再继续写。

| 按钮 | 作用 |
| --- | --- |
| 保存 | 写入当前文件，只提交该文件并尝试推送 |
| 上传笔记 | 获取远端状态，提交本机同步范围内的改动，合并需要的远端更新，再推送 |
| 下载更新 | 获取并合并远端更新；不会替你提交、丢弃或临时藏起本机改动 |

## 上传范围

包括本机新增、修改与删除的 Markdown 和常见附件：PNG／JPEG／GIF／WebP／AVIF／SVG、MP3／M4A／WAV／OGG、MP4／WebM、PDF；单文件不超过 20 MB。

遵守 `.gitignore`，排除隐藏目录、`node_modules`、根目录 `AGENTS.md`／`SKILL.md` 和其他文件类型。页面可以展开查看哪些改动被纳入或排除。

这个筛选限制的是插件自动提交的文件；**已有 Git 提交会整体随分支推送**，不会重新按文件类型过滤其中的内容。

## 同步受阻时

| 提示或情况 | 处理方式 |
| --- | --- |
| 有未提交笔记，无法下载 | 先保存草稿并上传笔记，再下载 |
| 范围外的已跟踪文件被修改 | 先在 Git 中处理这些改动，插件不会自动替你提交 |
| 未追踪的本机配置 | 不会被清除；与远端重名时 Git 会阻止覆盖 |
| 有尚未结束的合并或变基 | 先在 Git 中处理完，再同步 |
| 两台电脑改动冲突 | 上传中的变基会中止并恢复本机提交，回执列出冲突；在 Git／Obsidian 中解决后重试 |
| 登录、权限或网络错误 | 依据回执修复；已保存的本机内容仍保留 |
| 改动过多 | 每次最多自动提交 500 个文件，并限制命令长度；在 Git 中分批提交后再上传 |

同步使用当前分支的跟踪远端，不强制覆盖远端。页面计数来自最近获取的远端状态，每次上传或下载都会重新获取。
