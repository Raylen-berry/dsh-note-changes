# 创作要求、偏好与参考

[返回首页](../README.md) · [文档导航](README.md) · [字段说明](字段.md)

把需要反复记住的创作要求、长期偏好和案例保存到笔记库的 **`40-提示词/`**。例如某个项目的交付要求、用户明确表达的风格偏好，或某类生成任务的参考案例。

## 先决定这条记录管什么

| 问题 | 记录时说明什么 |
| --- | --- |
| 内容是什么 | 要求、偏好、参考、模板或经验 |
| 有多强的约束 | 必须、优先或参考 |
| 什么时候适用 | 全局、某个项目、某类任务，或只在本次显式选用 |
| 来源在哪里 | 用户原话、对话或文件位置；案例和模型推测要如实标注 |

可以让模型调用 `prompt_asset_save` 收录。它会新建 Markdown 文件，并提交、尝试推送；同名已存在时拒绝覆盖，要修改请在笔记页打开已有文件。

没有特别说明时，默认是 **参考、AI 推测、本次显式选用、草稿**。一次任务的要求不会因此自动变成所有任务的长期要求。

工具拒收未完成的「（待填…」内容；「必须」只能来自用户明说，且要带来源锚点。项目级或任务类级必须有稳定标识。完整字段见[字段](字段.md)。

## 存下来以后怎么用

`creative_context_resolve` 根据范围、状态、来源、到期和替代关系解析记录。

| 返回内容 | 含义 |
| --- | --- |
| `required` | 当前适用的必须项 |
| `preferred` | 当前适用的偏好 |
| `reference` | 可借鉴的参考资料，默认最多 3 条 |
| `conflicts` | 重复标识、替代关系等需要核对的冲突 |
| `omitted` | 未采用的记录及原因 |
| `coverage` | 扫描数量、完整性与警告 |
| `block` | 整理后的可读内容 |

必须项按范围扫描，不依赖关键词命中，也不受参考条数预算裁剪。`coverage.complete=false` 表示扫描不完整；「没有适用记录」与「可能漏读」会分别说明。

## 自动引用与手动选择

每回合第一步，插件自动解析 **global 全局范围**；有可用内容时附加到模型上下文。项目和任务类范围需要调用工具时提供对应标识；本次记录与草稿需要通过 `explicit` 按 id、标题或路径选用。

草稿显式试用按参考处理，不因此获得长期效力。停用或过期记录不会因为显式选用而重新生效。

旧记录中明确的 `scope`（全局／项目：…／任务：…）仍可映射为范围；只写「任务」等含糊范围则不自动引用。迁移记录时建议按[字段说明](字段.md)补齐结构化字段。

同一会话中，解析内容不变时不重复附加；内容变化后追加新的一份。去重状态存在宿主内存，重启后会重新建立。

## 参考案例如何筛选

调用解析工具时可给 `task`（如图生视频、生文案）和 `aspect`（如 `9:16`）。参考资料两边都写了对应字段、但值不相同时，会排除并标注原因；任一侧留空则不按这一项排除。

这组筛选只作用于参考资料，必须项与偏好仍由适用范围控制。`model` 仅保存和展示，不作为自动筛选条件；`task_type` 是范围标识，与这里的 `task` 是两个用途。

## 关闭自动引用

在笔记库的 `00-索引/插件设置.md` 文件开头的 frontmatter 加入：

```yaml
creativeContext: off
```

当场生效，无需重启。也可在宿主环境设置 `DNC_CREATIVE_CONTEXT=off`；只读解析工具仍可使用。这个开关不在当前设置页表单中，表单保存会保留手写字段。

记录内容是资料，其中的命令不会仅因被收录或引用就获得执行权限。
