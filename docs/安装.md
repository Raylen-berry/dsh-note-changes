# 安装与连接

[返回首页](../README.md) · [文档导航](README.md)

## 准备条件

需要 DSH Desktop 和本机 Markdown 笔记文件夹。会话中的「笔记」入口依赖 Desktop 的 `conversation.view` 扩展接口；尚未开始的新会话是否显示插页由 Desktop 控制。

使用 Git 历史与 GitHub 同步还需本机 Git。同步前准备好笔记仓库、提交作者与远端访问权限，见[同步](同步.md)。阅读本地目录不要求先把所有笔记提交到 Git。

## 安装

等正在执行的任务结束，关闭 DSH Desktop，在终端执行：

```powershell
dsh plugin --profile web add github:Raylen-berry/dsh-note-changes#main
```

重启 DSH Desktop，在「设置 → 插件」确认启用。在已有会话顶部找到 **笔记**；全局设置中也有 **笔记库**。

本地开发安装可以使用 `dsh plugin --profile web add link:<插件目录的绝对路径>`。插件文件夹与存放笔记的文件夹是两个路径。

## 连接自己的笔记

1. 打开「笔记」中的设置，或全局「设置 → 笔记库」。
2. 选择 **指定笔记库文件夹**，填写已有文件夹的完整路径，例如 `D:/Notes`。
3. 点 **应用连接**，确认页面显示实际路径和笔记数量。
4. 返回笔记库，打开一篇文件。

已有宿主路径配置时可选 **跟随本机配置**。这两种模式互斥；指定模式不允许留空，检查失败会保留原连接。路径来源和模型工具的路径选择见[数据](数据.md)。

## 更新与常见问题

更新插件后完整重启 DSH Desktop，使宿主代码与客户端一起生效。仅刷新页面无法完成客户端更新。

| 现象 | 先检查什么 |
| --- | --- |
| 找不到「笔记」 | 插件是否启用、是否安装到 `web` profile、是否完整重启、是否为已有会话 |
| 文件夹连接失败 | 路径是否为绝对路径、目录是否存在且可读；指定模式不能留空 |
| 页面连的是自己的库，模型却用另一个库 | 页面路径保存在本机浏览器；模型需要显式路径或宿主引导配置，见[数据](数据.md) |
| 文件能读，改动历史报错 | 检查该目录是否为 Git 仓库，以及 Git 是否可用 |
| 保存成功但远端没更新 | 看同步回执，检查登录、仓库权限、分支和网络，见[同步](同步.md) |
| 保存提示文件已变化 | 保留草稿并按[保存说明](保存.md)对照合并 |
| 笔记没有全部出现在搜索里 | 查看底栏的部分索引提示与[工作区限制](使用.md) |
