# 草稿、保存与冲突

[返回首页](../README.md) · [文档导航](README.md)

## 草稿什么时候留得住

切换笔记、切回对话或切换笔记库时，未保存内容会暂存在当前浏览器会话。刷新后重新打开相应笔记可恢复；关闭浏览器会话后不保证保留。

草稿暂存在 `sessionStorage`，仍需点 **保存** 或按 **Ctrl/Cmd+S** 写回本机文件。浏览器存储不可用时应先复制草稿；草稿不会随 GitHub 同步到另一台电脑。

## 保存会做什么

1. 核对打开时的正文版本与当前磁盘内容。
2. 通过宿主文件服务按版本做原子替换。
3. 只暂存并提交当前文件，尝试推送到已配置的远端。

推送失败会显示具体回执，本地保存内容仍保留。修复推送问题后，可以点 **上传笔记** 继续同步已有本地提交；它也会纳入同步范围内的待提交改动，先查看清单，见[同步](同步.md)。

手动保存独立于「会话结束时记录要点」开关。Git 操作与自动日记写入按笔记库排队，不会把其他已暂存文件混进当前文件的提交。

## 外部编辑冲突怎么处理

Obsidian、另一窗口或自动日记改过文件时，保存会拦截并保留草稿。

1. 打开 **对照合并**，左边看磁盘新版，右边看自己的草稿。
2. 每处差异选择磁盘、草稿，或两段都保留；相同内容自动保留。
3. 全部选择完成后应用到草稿，检查结果，再手动保存。

长文超过差异计算预算时按整篇对照。合并完成后若磁盘再次变化，保存仍会拦截，不会跳过版本检查。

这里处理的是同一文件的编辑冲突；GitHub 同步产生的 Git 冲突需要按[同步说明](同步.md)处理。

## 编辑边界

超过 60,000 字符只预览，不能把截断内容写回；超过 1 MB 的单篇在 Obsidian 中打开。宿主文件服务不支持版本保护时也会拒绝编辑。

新建使用原子的 create-if-absent，同名文件已存在时不会覆盖。
